# 按模型注入提示词

按当前模型步骤将要调用的模型，向系统提示词追加不同指令。

## 功能

- 注册一个系统提示词段落（默认 `order: 9500`，默认段落名 `deployment:model-instructions`）。每次组装系统提示词时读取当前步骤的提供商/模型，把命中的规则按声明顺序拼接；因此同一会话中途切换模型后，下一步就会使用新模型的指令。
- 匹配对提供商 id 和模型 id 分别进行：`*` 匹配任意长度，`?` 匹配单个字符，大小写不敏感且必须整体命中。提供商或模型列表为空表示不限；没有规则命中时段落为空，提示词保持原样，不占 token。
- 浏览器半边在 **设置 → 按模型注入** 注册设置页与导航图标，通过 `ctx.remote.settings` 读写设置文档中 `model-instructions` 命名空间的 `rules` 字段。保存后 Host 立即使用新规则，不重挂插件、不重启。
- 提供商和模型下拉来自当前部署可路由的模型目录（与对话框里的模型选择器同源），并提供「自定义通配符…」手填；目录暂时读不到时页面会提示，仍可手填。
- 设置页支持添加、删除、上移/下移、单条/整体收起规则，显示「未生效」「全部模型」状态，并提供放弃修改、重新加载、只读与未保存提示，以及保存冲突检测。

## 使用

1. 打开侧边栏底部的 **设置**，在左侧选择 **按模型注入**（紧跟「模型」一项）。
2. 规则默认为空，此时所有模型的系统提示词保持原样、不占用任何 token。
3. 点 **添加规则**，填写：

| 字段   | 含义                                                                                                          |
| ------ | ------------------------------------------------------------------------------------------------------------- |
| 规则名 | 可选，用于在列表里区分规则；留空时标题显示为「提供商 · 模型」。                                               |
| 提供商 | 从当前可路由的提供商中选择；「全部提供商」表示不限。需要通配符时选「自定义通配符…」手填。                     |
| 模型   | 从所选提供商当前可路由的模型中选择；「全部模型」表示不限。需要通配符或列表外的模型时选「自定义通配符…」手填。 |
| 指令   | 命中时追加到系统提示词的文本。留空的规则不生效，可用来暂时停用一条规则。                                      |

4. 点 **保存**。改动写入当前 profile 的配置，下一个模型步骤就按新规则拼装提示词；会话中途切换模型时同样在下一步生效，不需要重启。

通配符支持 `*`（任意长度）和 `?`（单字符），匹配不区分大小写且必须整体命中：`deepseek-reasoner*` 命中 `deepseek-reasoner-max`，不命中 `deepseek-flash`。所有命中的规则按列表顺序用空行拼接，所以可以先写一条通用的、再写一条针对具体模型追加的。

每张规则卡片的标题显示规则名（留空时显示「提供商 · 模型」），点标题左侧的箭头即可收起或展开这一条；收起后标题下方会保留一行指令摘要。列表上方的「规则列表」也是同样的箭头样式，点一下即可整体收起或展开全部规则。

卡片还会标出状态：**未生效** 表示指令为空，**全部模型** 表示没有选择提供商和模型、会命中所有模型（页面底部另有提示）。规则右上角的 ↑ ↓ 调整顺序（顺序影响拼接结果），**删除** 只改动当前草稿。

**放弃修改** 把编辑框恢复成已保存的内容，**重新加载** 重新读取 Host 上的当前配置。有未保存修改时 **重新加载** 不可用，避免误丢草稿；如果保存时提示配置已被其它改动更新，你的草稿会保留、最新配置会被重新载入，再次保存即可。

配置只读时页面会标出且无法保存；如果暂时读不到模型目录，页面会提示，此时仍可用「自定义通配符」手填提供商/模型 id。

## 配置

| 键            | 类型    | 默认值                          | 说明                                               |
| ------------- | ------- | ------------------------------- | -------------------------------------------------- |
| `order`       | number  | `9500`                          | 段落位置：交付物引用之后、结构化输出之前。         |
| `name`        | string  | `deployment:model-instructions` | 段落名；同名的 Agent 级段落会遮蔽它。              |
| `interpolate` | boolean | `false`                         | 是否对指令文本做 `{{变量}}` 插值；默认按原样注入。 |
| `rules`       | array   | `[]`                            | 有序规则列表，只在设置页编辑。                     |

设置页只编辑 `rules` 这一个字段；其余字段仍写在配置行里，改动它们会让插件按常规重新应用一次：

```yaml
- id: model-instructions
  name: '@nick.du/dsh-plugin-model-instructions'
  config:
    order: 9500 # 段落位置
    name: deployment:model-instructions # 段落名
    interpolate: false # 是否解析 {{变量}} 插值
    rules: [] # 由设置页维护
```

覆盖时请整套提供 `config`：Loader 的覆盖会替换整份配置，而不是逐字段合并。

`rules` 存的是字符串列表：界面上选择单个提供商/模型时写入单元素列表，「全部」写入空列表，「自定义」写入按逗号拆分的通配符；手写 YAML 配置同样要写成列表。

## 安装

### 从 npm（发布后）

在 DeepSeek Harness 中打开 **插件 / Plugins** 页面，选择 **添加插件 / Add plugin**，输入包名 `@nick.du/dsh-plugin-model-instructions`。DSH 会校验 `engines.dsh` 与当前版本是否兼容，并加载预构建的 `lib/`。

### 从本地目录（开发）

1. 构建：`pnpm --filter @nick.du/dsh-plugin-model-instructions build`
2. 在 DeepSeek Harness 中打开 **插件 / Plugins** 页面，选择 **添加插件 / Add plugin**，选中本插件目录（`plugins/model-instructions`，不要选仓库根目录）。
3. 在**新会话**中打开 **设置 → 按模型注入**，添加一条规则并让模型回答一次，确认指令已注入。

如果之前装过原插件 `@local/model-instructions`，请先在插件页面把它移除：迁移后的 bundle 仍使用 Loader 行 id `model-instructions`（设置页和 volatile 的 `rules` 字段都以该 id 为键），两个 bundle 无法同时插入同一行 id。迁移后的包名不同（`@nick.du/dsh-plugin-model-instructions`），旧页面上的规则不会自动迁移；切换后请在新设置页重新添加规则，或把 `rules` 列表抄进 profile 的 patch 层。

## 限制

- 段落是 profile 级全局贡献：所有会话和子代理都会看到命中的指令。
- 只影响提示词文本，不改变工具、模型路由或任何会话状态。
- `minimal` 预设的人设声明了完整提示词（`complete: true`），该预设只发送人设前缀，本插件的段落会被忽略；`standard`、`ptc`、`cordis` 正常生效。
- 指令文本默认按原样注入，不做 `{{变量}}` 插值，因此正文里出现花括号也不会让拼装失败；需要插值时把配置行的 `interpolate` 设为 `true`。
- 匹配针对提供商/模型 id，不针对显示名；下拉列表来自当前部署可路由的模型目录，目录读不到时只能手填。
- 本插件从 `@local/model-instructions` 迁移而来，行为与配置字段与原插件一致。
